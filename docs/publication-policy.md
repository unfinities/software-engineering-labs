# 公开内容与脱敏规则

本仓库公开。原始下载的 detail.htm 可能夹带页面资源和会话数据，因此只上传经阅读整理的课程约束，不上传网页源码或原 ZIP。真实访谈中如有身份、联系方式或凭据，先脱敏再发送给 AI，使完整 AI 记录能够公开。

## 不进入 Git 的内容

- 密码、访问令牌、API 密钥、私钥、认证 Cookie、会话标识、带凭据的连接串。
- 私有接口地址、内部服务配置、真实用户或生产数据。
- 学号、电话、地址等非必要身份信息；chat.txt中用户本次主动加入并要求保留的参与人姓名保留，其余身份字段不扩展。
- 原始录音、未脱敏访谈、课程网页源码、原始下载包、最终个人提交 ZIP。

本地使用 private/ 保存敏感材料。Gitignore 只是第一道防线，不能清除已提交历史，也不能保证手动强制添加的文件安全。

## 检查和记录

1. 上传前人工检查文件清单、差异及 PDF。公开记录一般使用角色代号，本次用户指定保留的参与人姓名按其修改保存；用 `[已脱敏：类别]` 明示替换，保留行号和实际业务含义。
2. 提交钩子扫描暂存区的实际内容；推送钩子和 CI 扫描全部可达历史。扫描报告只列路径和规则名，不显示匹配的秘密。
3. PDF 提取文字和元数据后扫描，损坏 PDF 或带附件的 PDF 拒绝上传。未知二进制默认拒绝，避免内容未经检查即公开。
4. 自动规则能识别常见令牌、私钥、凭据赋值与带认证 URL；不能保证识别截图中的文字、所有内部地址或所有个人信息，仍需人工检查。
5. 若误泄漏，立即停止推送、撤销相应凭据，再处理历史；仅删除最新文件不能撤销泄漏。

GitHub remote 使用正常 HTTPS URL，不把令牌嵌入 URL。认证交给本机凭据管理器；Git 作者邮箱使用 GitHub noreply。

后续确需增加新文件类型时，先补充检查能力并审阅后再纳入白名单，不绕过检查。
