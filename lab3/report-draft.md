# 校园二手交易系统软件实现与构建

软件工程实验三 AI辅助报告初稿，个人审查记录待本人补充。公开版省略学号姓名，运行截图只放个人Word。

## 1 实验目标与实现范围

本实验在校园二手交易系统的需求分析和软件设计基础上，将实验2中的领域关系、状态转换和交互流程实现为可编译运行的C++桌面程序。交付内容包括Windows原生图形界面、SQLite持久化业务层、PlantUML实现图、CMake构建工程和自动化测试。应用支持多个窗口分别登录不同账号，在同一台电脑上共享数据。

本次实现保留注册登录、商品草稿与审核、组合查询、预约及线下交接、违规处理、统计和日志七个逻辑模块。网页导航改为桌面窗口；查询计时改为从桌面发起查询到文字列表重绘。该适配已由需求方确认。在线支付、物流、聊天、自动超时、退款仲裁和已完成交易回退仍不在本期范围。

### 2.2 状态图与时序图的落实

商品八态和预约六态落实在命令处理分支及数据库CHECK约束中。每件商品最多一条有效预约，由部分唯一索引约束；商品已预约对应预约等待确认，商品待交接对应预约待交接。已售出状态在应用规则之外另有数据库触发器禁止回退。

预约时序落实为：校验会话与归属，获取BEGIN IMMEDIATE写锁，检查同次请求回执，再重检状态与版本；随后更新商品、保存预约及快照、加密联系、写成功日志和回执，最后统一提交。任何步骤失败则回滚，失败日志在事务外独立写入。图中的命令协调与授权逻辑实际由Service内部方法协同完成。

## 3 核心业务与数据一致性

### 3.1 预约交易和下架

买家预约已发布的他人商品时提供联系方式，系统保存标题、价格和地点快照。卖家在等待确认阶段接受或拒绝；接受时提供自己的联系方式。待交接阶段任一方填写原因可以取消，只有卖家能够确认完成，界面先显示“请确认已经完成线下交接，完成后不可撤销”。正常服务方法也要求确认标记，避免仅依赖按钮显示。

卖家可以下架自己的已发布、已预约和待交接商品。有有效预约时必须填写原因，商品变为已下架，预约变为已终止，成功日志与业务同步保存。违规处理由管理员执行并保留原因和历史。已售出违规仅追加处理记录并从公开查询中排除，成交状态和历史金额不回退。

### 3.2 并发和同次操作重发

每次提交使用随机request_id，并保存命令内容摘要。同一账号同一request_id已成功时，只返回原结果编号，不重复执行或生成成功记录；编号相同但内容不同会拒绝。成功回执在业务事务内保存，临时故障且未提交业务时允许重试同次命令。所有重发先检查当前登录与权限，退出登录后不能直接获取旧成功结果。

SQLite通过写事务锁协调同机多个进程或连接，唯一有效预约索引进一步防止多人抢占。旧页面携带对象版本，提交前重新检查。锁等待超过5秒返回处理中提示，可稍后重试；这是当前本机实现的处理方式，不承诺任意竞争压力下立即返回。

### 3.3 敏感数据与审计

密码使用随机盐和PBKDF2-HMAC-SHA256的600000次迭代结果保存，不存明文。管理员邀请码由运行时随机生成，仅保存摘要，成功注册后不可再次使用。程序没有固定内置账号、密码或API凭据。联系方式使用Windows DPAPI加密，绑定同一Windows账号和机器。

预约列表不含联系方式或其密文；详情每次根据当前身份和预约状态决定返回字段。预约结束后买卖双方不能再通过详情或历史请求取得联系，管理员在管理需要下可查看。成功日志和回执只存业务标识；失败日志只存静态错误类型、时间、动作、对象、可知身份和请求编号，不保存敏感输入或完整请求。

成功日志写入失败会触发业务回滚；回滚后的失败记录独立保存。数据库日志仍不可用时，系统追加到本机故障文件，恢复后管理员查询会合并展示。若数据库和本地文件均不可写，程序明确报告该双重故障。运行数据位于本机用户目录，具有该目录访问权限的操作系统用户属于部署信任边界。

| 出现的问题 | 本轮实际处理 |
| --- | --- |
| 代码风格工具重排Windows头文件后编译失败 | 恢复基础Windows类型头先于加密SDK头，并对该依赖块关闭自动重排；补全直接依赖与括号后重新编译 |
| 同秒审核记录顺序与业务预期不符 | 补充测试发现随机编号排序问题，改用时间和实际写入rowid排序 |
| 窗口筛选标签挤压 | 缩短文本并限制各标签宽度，重新启动测试窗口复查 |
| 设计时序与代码事务顺序不完全一致 | 以实际Execute实现为准重绘预约时序，明确写锁内查询回执和返回编号后再查询详情 |
| GitHub的MSVC链接失败 | 日志定位为自带清单与链接器生成清单重复；保留app.rc中的清单并关闭链接器的第二份清单，修复后远程构建和测试通过 |
