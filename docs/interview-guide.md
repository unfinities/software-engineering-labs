# 访谈提纲

本文件是问题准备，不是甲方答复。实际对话发生后才写入 chat.txt 并使用 INT-01-L001 等行号。记录真实时间、参与角色代号及渠道；不要先填虚构答案。

## INT-01 正式访谈

| 提纲号 | 主问题 | 追问方向 |
| --- | --- | --- |
| Q01 | 选择哪个规定项目，当前最需要解决什么问题？ | 用户对象、使用情境、成功标准、明确不做什么 |
| Q02 | 至少三类用户分别能做什么？ | 同一人多角色、数据归属、他人记录、管理员边界、越权结果 |
| Q03 | 一笔核心业务从开始到结束如何进行？ | 触发者、前置条件、每一步成功结果、失败与取消 |
| Q04 | 核心对象有哪些状态？ | 至少四个真实有效状态；谁可转换、转换条件、禁止转换、终态 |
| Q05 | 必须保存哪些数据，如何关联？ | 唯一标识、不可重复条件、删除/更正、同步更新和历史保留 |
| Q06 | 如何处理多人竞争最后一份资源？ | 哪个请求成功、失败反馈、有效记录唯一性、一致性验收 |
| Q07 | 重复点击、请求重发或旧页面操作怎么办？ | 原结果复用、状态重检、是否允许重试、不重复扣减/登记 |
| Q08 | 超时、取消或其他失败怎么办？ | 时限从何时算、恢复/补偿、权限、关联状态和日志 |
| Q09 | 需要哪些查询、统计或导出？ | 筛选组合、权限、统计口径、时间边界、零结果 |
| Q10 | 哪些关键操作需要留痕和查询？ | 操作者、时间、对象、前后状态、结果、可见范围、敏感字段 |
| Q11 | 性能、安全、可靠性等如何验收？ | 测试环境、数据量、并发、样本数、响应阈值、失败计入方式 |
| Q12 | 哪些答案尚不确定或互相矛盾？ | 逐项列入待确认清单，确定跟进方式与确认人 |

选题后同时对照 project-options.md 对应行，逐项询问未覆盖业务，避免通用提纲漏掉该选题要求。

## INT-02 跟进沟通

至少开展一轮真实跟进。可围绕 INT-01 中含糊、遗漏或矛盾的回答补充，或核对整理初稿。

- 用明确的两个场景询问状态冲突、并发或取消规则，记录甲方选择及理由。
- 逐项确认权限、四个以上业务状态、数据唯一性、跨对象更新规则。
- 把“快、安全、稳定”转为对象、条件、数字/可判断的标准，不代替甲方定阈值。
- 确认至少一种统计的口径，至少两类异常的处理结果。
- 对拟标为已确认的需求逐条指出证据；没有答复的项目保留待确认。

## 接收访谈材料时

保留原始文字和时间，按真实对话顺序编号。敏感原件仅留 private/；在发送给 AI 前完成脱敏，使 AI 交互记录可以完整公开。已发送给 AI 的内容如需脱敏，必须在公开记录明确注明，不伪称为完全未改动原文。
