## 1 项目概况

校园二手信息在群聊中分散，商品售出后未及时更新，多人可能重复预约。本项目目标是通过发布审核、统一查询、唯一有效预约和交易结果记录，让商品状态与交易处理保持一致。

每条商品对应一件物品。系统覆盖普通账号及管理员身份、商品审核与违规处理、查询和预约、卖家确认、统计及日志；普通账号可同时承担买卖角色。

双方线下联系、付款、交接。本期不实现在线支付、物流、即时聊天、评价、推荐、学校认证、自动预约超时、联系方式修改、申诉、仲裁、退款及交易状态纠错。实验1只完成需求分析，验收方法是后续实现后的验证计划。

## 2 整体业务分析

### 2.1 主要业务流程

| 阶段 | 主要处理 | 分支及失败处理 |
| --- | --- | --- |
| 注册及登录 | 普通用户以唯一用户名注册，管理员用一次性邀请码 | 未登录只浏览，越权拒绝；退出后的重发同样检查身份 |
| 发布审核 | 卖家草稿完整后提交，管理员通过后发布 | 驳回需原因；修改先回草稿重审，有有效预约不得修改 |
| 查询预约 | 按关键词、分类、价格、状态组合查询，买家预约他人已发布商品 | 记录标题、价格和地点快照；并发只允许一条有效预约 |
| 接受及交接 | 买家预约时填联系，卖家接受时填自身联系，双方线下交接 | 拒绝需原因；等待确认买家可取消，待交接任一方带原因可取消 |
| 完成及下架 | 卖家二次确认完成；卖家三态可下架，管理员处理违规 | 完成不可撤销；有效预约下架时商品、预约及成功日志整体生效 |

预约不自动超时。完成前提示“请确认已经完成线下交接，完成后不可撤销”；完成后争议保留历史、线下解决，管理员也不能回退在售。

### 2.2 主要数据关系

| 对象 | 关联和保存内容 | 一致性要求 |
| --- | --- | --- |
| 用户与角色 | 关联商品卖家、预约买家、审核及日志操作者 | 用户名和记录编号唯一，密码不得明文保存 |
| 商品 | 卖家、内容、分单位价格、地点、状态及违规锁定 | 一条一物；价格0.01至99999.99元且两位小数 |
| 预约 | 商品、买家、阶段、商品快照、双方私有联系、结束原因及完成时间 | 商品最多一条有效预约，结束记录不复用，历史金额用预约价 |
| 审核及违规 | 商品、管理员、结论、原因与处理历史 | 已售出违规仅追加，不删除历史或回退状态 |
| 成功和失败日志 | 操作对象、身份、时间、动作、结果及原因 | 成功日志与业务同步；失败日志不随业务回滚，故障时可先本地留存 |

预约、接受、取消、下架、完成时，商品、预约及成功日志整体生效或全部不生效。失败日志记录已到服务端的失败，未登录不虚构身份；不记录密码、联系方式、邀请码原文或含这些内容的完整请求。

### 2.3 业务状态及允许转换

| 商品状态 | 允许转换 | 限制 |
| --- | --- | --- |
| 草稿 | 提交至待审核 | 不直接发布 |
| 待审核 | 通过至已发布；驳回至已驳回；撤回至草稿；违规下架 | 不直接修改 |
| 已驳回 | 修改至草稿，再提交 | 不跳过审核 |
| 已发布 | 预约至已预约；撤回至草稿；下架 | 仅预约他人当前可预约商品 |
| 已预约 | 接受至待交接；取消或拒绝至已发布；下架 | 不直接完成或修改 |
| 待交接 | 完成至已售出；取消至已发布；下架 | 取消与完成不同时成功 |
| 已售出 | 无回退，违规仅追加记录 | 不下架、不重约、不恢复在售 |
| 已下架 | 未锁定时修改至草稿，再审核 | 锁定须解除后才可修改 |

预约有效状态为等待确认、待交接，分别与商品已预约、待交接配对；结束状态为已取消、已拒绝、已终止、已完成，不能复用记录。其他商品状态没有有效预约，未列明的状态转换均禁止；违规锁定为附加标记。

### 2.4 权限和隐私

买家仅处理自己预约，卖家仅管理自己的商品；管理员审核、违规管理、平台统计与日志查询，不代替交易双方完成交接。公开列表仅含非违规的已发布、已预约、待交接及已售出商品；卖家可查自己的全部商品，管理员可查全部。

| 预约阶段 | 卖家读取买家联系 | 买家读取卖家联系 |
| --- | --- | --- |
| 等待确认 | 买家预约成功后可读 | 卖家未接受并提供前不可读 |
| 待交接 | 可读 | 卖家接受成功后可读 |
| 取消、拒绝、终止、完成 | 不可读 | 不可读 |

访问限制覆盖历史页、直接请求及成功请求重发；结束后联系仍私有留存，管理员因管理可查，公开页面及日志始终不展示。本期填错联系方式只能取消重约。

### 2.5 查询、统计与异常

关键词匹配标题或描述任一字段，其他条件同时满足；价格两端包含，下限高于上限拒绝。成交按北京时间的实际完成时间统计，从开始日00:00至结束日次日00:00前，金额用预约价，取消、拒绝、终止均不计入；卖家查自己，管理员查全平台，并可统计各状态商品数量。

| 场景 | 处理规则 |
| --- | --- |
| 多人竞争/旧页面冲突 | 只允许符合当前状态的操作成功，不能产生多条有效预约或矛盾状态 |
| 重复及重试 | 同次成功复用结果、处理中不重执；临时保存失败重检后可重试，取消重约为新操作 |
| 有预约下架/保存故障 | 商品下架、预约终止、成功日志整体保存；失败全部不生效，失败日志独立留存 |
| 已结束仍读联系 | 双方历史页和直接请求均拒绝，不能用重发旧成功结果绕过当前访问规则 |
