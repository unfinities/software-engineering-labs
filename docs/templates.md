# 填写模板

以下为结构模板，不代表实际需求、对话或审查结果。复制后依据真实材料填写；不要直接计入课程数量。

## 十字段需求

```markdown
## REQ-001 [实际需求名称]

- 类型：[功能需求／非功能需求／约束]
- 来源：[真实 INT 行号；或 COURSE 编号]
- 优先级：[高／中／低]
- 状态：待确认
- 需求描述：[一个主要目标]
- 前置条件：[触发前必须满足什么]
- 正常结果：[完成后用户可观察的结果]
- 异常或边界情况：[实际约定的处理；未约定则注明待确认]
- 验收方法：[输入、操作、预期结果及通过标准]
- 关联需求：[无或其他稳定 REQ 编号]
```

不把未确认的业务猜测标为已确认；编号一经分配就不重排、不复用，撤销时更新状态并保留理由。

## 首次 AI 需求整理提示词（访谈后使用）

```text
请根据下方完整的课程要求、所选项目和真实访谈，生成第一次完整 requirements.md。
每条从 REQ-001 起使用唯一稳定编号，严格依次保留十个字段。
每条只描述一个主要目标，不重复拆分凑数；不要扩大范围或编造甲方答复。
来源必须对应提供的真实 INT 行号或 COURSE 约束。缺少确认的规则标为待确认。
对状态、权限、数据关系、一致性、异常处理及可测量的非功能要求进行整理。
若现有材料不足以满足课程数量或验收要求，请列出待确认问题，不能编造已确认条目。
输出完整文档，不用“同上”或省略号替代字段。

【课程要求全文或完整适用约束】
[粘贴实际发送的完整文本]
【所选项目及其最低范围】
[粘贴实际项目与约束]
【正式访谈与跟进沟通全文】
[粘贴实际 INT 行号、时间和对话]
```

发送前脱敏；把实际使用的提示词、完整输入和完整首次输出都复制到 chat.txt，而不是只保存此模板。首次结果原样写入 requirements.md，完成对应提交并创建 lab1-ai-draft，之后才开展本人审查。

## 人工审查记录

```text
## REV-001
- 相关需求：[实际 REQ 编号]
- AI 原始内容：[被核对的原文]
- 发现的问题：[遗漏、编造、矛盾、无法验收等；或核对无误]
- 核对依据：[真实访谈来源或课程要求]
- 最终处理：[保留／修改／补充／删除]
- 处理理由：[实质性原因]
```

至少三项真实核对，不要求每项都修改；不刻意制造错误，不用调整排版充数。
